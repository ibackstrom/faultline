The original report is Shehroze Talat's issue #6201. The correction is Cross2pro's PR #6232, open when checked on 21 October. We didn't discover the original bug or write that patch. Our contribution is the independent replay, nearby cases and recorded output.

The narrow timing window

The setup combines FilterIncompleteUserTurnStrategies with FunctionCallUserMuteStrategy. Inference starts while the logical user turn is still open. The user starts speaking again before the model commits to its tool call.

  1. Start inference after the first speech segment ends.
  2. Resume speech while that inference is still running.
  3. Start the tool, then send the speech-stop event while input is muted.
  4. Return the tool result. Watch for actual answer text, not just a completed tool.

On the original revision, the muted stop event leaves speaking state stuck. The result reaches the conversation context, but the next inference is held. The watchdog doesn't rescue this sequence.

The patch keeps voice-activity state synchronized during mute and releases the held context when the user turn closes. Both parts matter: our no-mute and stop-after-result cases closed the turn on the original code, yet still produced no answer.

What the replay actually recorded

We used the real pipeline, aggregators, turn controller and function dispatch. Only speech events, model decisions and availability data were scripted. A pass requires the expected pre-TTS text, exactly one tool call, exactly two inference requests and a closed turn before teardown.

The controls caught our mistake too

Our first recorder sat after an aggregator that consumes text. It called even the ordinary control silent. We discarded those classifications, moved the recorder before the assistant aggregator and repeated the full matrix. A final run explicitly initialized the scripted service's unsupported settings to remove a startup diagnostic. The cases stayed unchanged.

Four upstream test files also passed: 191 tests on the base and 194 on the patch. Those suites support the check; they don't turn it into a live-call test.
